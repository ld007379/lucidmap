01 / 它给你什么

你缺的不是勇气，
是一张能检查的图。

卡住的时候，三样东西通常混在一起：已经确定的事实、其实只是猜测的判断、和真正需要先去确认的条件。混在一起，任何选择看起来都像赌博。
清醒地图做的事很朴素：把它们一件一件分开摆好，让你看见自己在拿什么换什么。

A · 已知事实

只贴你写过的原话

每条事实都逐字来自你的输入，并标注「用户自述 · 未独立核实」。不替你补脑，也不假装知道你不知道的事。

B · 待确认缺口

把「不知道」单独列出来

哪些事没确认之前，先别急着拍板。缺口会编号，下一轮补上真实信息，图就跟着更新。

C · 三条路

A、B 之外，还有一条 C

在「维持现状」和「立刻改变」之外，先找一个成本更低、还能撤回的第三条路。每条都写清收益、代价、成立条件。

D · 下一步

不是「辞职去追梦」

而是48 小时内就能做完的那一步：一个电话、一次试探、一份简历。先小试一把，别一次梭哈。

E · 改主意条件

提前写好「什么情况下换路」

「如果三个月内没拿到 X，就换 B」。写在前面，才不会被沉没成本绑住。

F · 可以继续追问

补一条真实信息，图就会变

把「待确认」变成「已知」，也可以自己加一条它没问到的条件。越用越准，而不是一次性算命。

02 / 一次真实的拆解

从一段大白话，
到一张摊开的图。

下面这段是一份完整示例里原样使用的输入——没人教它怎么组织语言。
左边是原文，右边是图里长出来的东西，每一格都能对回去。

你写下的

我在成都读软件工程，今年六月毕业。老家在南充，父母希望我回去考事业单位，说这样稳定。我拿到了杭州一家公司的 offer，月薪 1.2 万，试用期三个月，房租大概 3500。家里说能支持我一年，可如果我坚持去杭州，父母不太高兴。我该去杭州，还是回南充？

125 个字 · 没分段 · 想到哪写到哪

→
它还给你的
事实 5

月薪 1.2 万、试用期三个月、房租约 3500；家里能支持一年；父母希望你回去考事业单位；父母只是不太高兴；应届身份有时限。 五条都能对回上面原文（措辞按报告口径做了归纳；「应届身份有时限」是从原文直接推出来的）。「南充有具体岗位」不在原文里——它被放进缺口，而不是当成事实。

缺口 3

杭州 offer 试用期后的转正条件和薪资是什么？父母是要你参加考试，还是已经联系好了单位？回南充能报的岗位和考试时间具体是什么？

第三条路

先去杭州，同时把南充的考试时间表摸清楚。 原来的二选一假设「去了杭州就不能考试」，但事业单位考试有固定时间表，入职后仍然可以报名。

下一步

未来 48 小时内：给父母打一次电话问清三件事（是要考试还是已联系单位、大概什么时候考、他们最担心什么），同时向 HR 确认试用期考核标准。

真正决定去留的，不是「稳不稳」，而是南充到底有没有一个具体的岗位，以及试用期后你还剩多少余地。

04 / 凭什么可信

它不装懂。
这一点写在产品里。

大多数「AI 建议」的问题是：听起来全对，但没法检查。
这里的每条结论都能追回你写过的原话，或者被明确标成「猜测」。

原则 01

原话就是原话

每条「已知事实」都逐字取自你的输入，旁边标着「用户自述 · 未独立核实」。它不替你把猜测写成事实。

原则 02

不知道，就说不知道

没底的部分单独成列，不进结论。你一眼能看出来：现在到底还差哪几件事。

原则 03

给条件，不给口号

不说「你应该」，只说「如果你更在意 X，就先走 Y；如果 Z 发生，就改回来」。判断权在你手里。

原则 04

先小试，别梭哈

优先推荐成本低、还能撤回的动作。为的是让你有退路，而不是逼你现在就全押。

「图上写的三条路，收益和代价都是条件分析，不是承诺。
任何一条成立与否，取决于你有没有把那些条件确认下来——这也是为什么它把下一步写成一件具体的小事。」 —— 产品说明里的原话，没有改过
边界

它不是算命，也不替你做决定。它不具备法律、医疗、财务资质，不能预测未来；它能做的是把你已经知道、但混在一起的思考整理成可以逐条检查的结构。最后拍板的永远是你。

06 / 隐私与成本

你的纠结，
不该变成别人的数据。

这是纯前端单文件页面：没有账号系统，没有后台，没有把内容上传到「我们」的服务器。打开网页、写完、关掉，内容只留在你自己的浏览器里。

⌂

纯前端，不经我们的服务器

页面本身只是 HTML。你的输入、历史、草稿存在浏览器的本地存储里，不注册、不上传。

Key 保存在本机浏览器，不写进页面、不经过我们。请求从你的浏览器直接发给你选的服务商。

↺

07 / 适合谁

它很好用，
但不打算对所有人有用。

把边界说清楚，比把话说满更有用。

✓适合

  • 你面前有两个或几个真实选项，来回权衡了好几轮
  • 信息不全，但你不想再靠「感觉」拍板
  • 想找一条比「全押」更稳的中间路
  • 想把这件纠结拿给别人看、一起讨论
  • 需要留个记录：三个月后回来看，当时是怎么想的

✕不适合

  • 需要法律、医疗、投资等专业意见（这属于专业资质问题）
  • 只是想把情绪倒出来、不想看分析
  • 指望它预测结果、替你承担决定的后果
  • 涉及他人隐私或不能描述清楚的事实
08 / 常见问题

用之前，
你可能想问的八件事。

如果这里没有，页面底部有 GitHub 仓库，可以直接开 issue 问。

要花钱吗？+

工具本身免费。不配 API Key 也能用本地引擎出一版规则图。只有当你选择云端模型时，才需要自己的 Key，费用由服务商按 token 收取——几百字的问题通常是几分钱到几毛钱的量级，报告顶部会显示本次消耗。

它准吗？能预测结果吗？+

不能预测。它不做预测，也不替你保证结果。它做的是把事实、猜测、缺口和条件分开摆好，帮你少在「已经知道的事」上反复内耗。判断和后果仍然在你。

一定要自己配 API Key 吗？+

不一定。默认有本地引擎，30 秒出一张规则版的图，内容不出你的浏览器。想要更细的证据引用、更准的条件和追问，可以配自己的 Key（DeepSeek / 通义千问 / Kimi / 硅基流动 / OpenRouter 任选其一）。

我写的东西会被谁看到？+

不经过我们的服务器——这个项目没有后端。本地引擎完全离线；云端引擎时，你的内容会从浏览器直接发给你选择的服务商，按对方的隐私政策处理。Key 和建议都只存在你本机浏览器里。

手机能用吗？+

能。同一个网址，手机浏览器打开即可，布局会自适应。用自己手机上的 Key 也只需要配置一次。

能导出、能分享吗？+

可以导出分享长图（PNG）、Mermaid 流程图和完整 Markdown。想拿去和同事、家人讨论，或者存档三个月后回看，都行。

会不会替我做决定？+

不会，也刻意不做。它给的是「如果你更在意 X，就先走 Y」这种条件化建议，以及「什么情况下该改主意」。最后一步永远留给你。

数据存在哪？换电脑会丢吗？+

存在浏览器的本地存储里，不跨设备同步。换电脑、换浏览器、清理浏览器数据都会变成一套新的空白数据。重要的图建议导出留档。

想自己改？

工作台本身就是一个单独的 HTML 文件，没有构建步骤。下载仓库（或桌面那份内嵌版）用编辑器打开就能改文案、改配色、改规则；改完双击即可运行。介绍页的截图放在仓库 assets/ 里，随仓库一起部署。
